# 云端音频透传服务 — 后端开发与对接说明

> **本文档的读者**：后端老师及其 AI 助手（Claude）。
> **任务**：实现并部署一个极简的 UDP 音频透传服务，使小智终端（ESP32-P4）在"仅连接手机热点"的外出场景下，能把 LLM 回复音频经服务器中转给手机 App（数智方舟智通音频中转站）播放。
> **工作量**：约 50~100 行代码 + 一台公网可达的服务器。**完成后客户端侧（终端固件 + 手机 App）可即插即用。**
>
> ⚠️ **状态更新（2026-08-16）**：外出场景已通过**组播方案**实测解决（详见《数智方舟智通音频中转站-对接说明.md》第十节——设备连手机热点 + 组播模式，零服务器零 root）。**本云端透传方案降级为可选增强**：仅在组播不可用的机型上、或需要跨地域/多设备管理的场景才需要。后端老师可暂缓实施本方案。

## 0. 背景（30 秒理解）

### 0.1 项目现状

- **终端**：小智 AI 聊天机器人（ESP32-P4 开发板，4.3" 触屏）。LLM 回复经 TTS 解码为 PCM 后，在板载扬声器播放。
- **已跑通的局域网方案**：终端把 PCM 旁路经 UDP 转发给同一局域网内的手机 App，手机经系统路由输出到蓝牙耳机。协议为自研轻量格式 XZFA/XZAD/XZAL（见对接文档《数智方舟智通音频中转站-对接说明.md》），已在家庭 WiFi 场景稳定运行。
- **卡点**：外出时终端只能连**手机热点**。Android 系统的 tethering 机制把热点客户端的进流量直接 NAT 到移动网络，**不投递到手机上的 App**（系统安全设计，广播/单播/任何协议均不可绕过，除非手机 root）。因此局域网方案在"纯热点 + 移动数据"场景失效。

### 0.2 云端透传如何解决

终端连手机热点后可正常访问外网。将音频帧**经公网服务器转发**：双方各自主动连服务器，NAT 全部由"先发制人"打通（服务器记录源地址后回发即可穿透）。

```
终端(连手机热点, 有外网)                   手机App(移动数据, 有外网)
    │  UDP 上行: 注册+音频帧                    │  UDP 上行: 注册
    ▼                                          ▼
┌────────────────────────────────────────────────────┐
│           云端透传服务器（本次要交付的东西）            │
│   按配对码(pair_code)建立 终端↔App 会话              │
│   终端发的包 → 原样转发给 App；App 发的包 → 转发给终端  │
└────────────────────────────────────────────────────┘
```

- 带宽：终端→App 单向音频约 **32 KB/s**；心跳与注册包可忽略。演示级负载任何服务器均无压力。
- 延迟：增加约 1 个 RTT（国内服务器一般 +30~100ms），对话体验可接受。

## 2. 协议规范（客户端 ↔ 服务器，全部小端字节序）

### 2.1 终端注册/心跳包 XZRG（终端 → 服务器，每 2 秒，14 字节）

```
offset 0  size 4  magic     'X' 'Z' 'R' 'G'
offset 4  size 1  version   0x01
offset 5  size 1  flags     0x00（保留）
offset 6  size 4  pair_code u32 配对码
offset 10 size 4  seq       u32 单调递增
```

### 2.2 App 注册/心跳包 XZRA（App → 服务器，每 2 秒，14 字节）

```
offset 0  size 4  magic     'X' 'Z' 'R' 'A'
offset 4  size 1  version   0x01
offset 5  size 1  flags     0x00（保留）
offset 6  size 4  pair_code u32 配对码（用户输入，与终端一致）
offset 10 size 4  seq       u32 单调递增
```

### 2.3 数据包（注册成功后，双向）

**客户端发来的任何非 XZRG/XZRA 包，服务器原样转发给同 pair_code 的对端。** 实际流量为：

- 终端 → 服务器：XZAD 音频帧（20 字节头 + ≤1000 字节 PCM，每 60ms 1~2 包）与 XZAL 心跳（8 字节，每 1 秒）。**服务器无需理解，原样转发即可。**
- App → 服务器：一般无数据包（仅注册心跳）。

> 注：XZAD/XZAL 的字节级格式定义在《数智方舟智通音频中转站-对接说明.md》第三节，服务器不需要实现其解析；但若智能体想写自测脚本，可参考该文档。

## 3. 服务端行为规范（状态机）

维护会话表：`pair_code -> Session`，其中

```
Session {
    device_addr: (ip, port) | null   // 终端源地址（来自最后一次 XZRG）
    app_addr:    (ip, port) | null   // App 源地址（来自最后一次 XZRA）
    device_last_seen: timestamp
    app_last_seen:    timestamp
}
```

处理规则（UDP 收包循环）：

1. **收到 XZRG**（magic 匹配 + version 0x01 + 长度 ≥ 14）：
   - 解析 pair_code，`session[pair_code].device_addr = 源地址`，刷新 `device_last_seen`
   - 日志：`[pair] device registered code=<hex> from=<ip:port>`
2. **收到 XZRA**（同上）：
   - `session[pair_code].app_addr = 源地址`，刷新 `app_last_seen`
   - 日志：`[pair] app registered code=<hex> from=<ip:port>`
3. **收到其他包**（长度 ≥ 4 即可转发，不校验内容）：
   - 若源地址 == 某会话的 `device_addr` 且 `app_addr` 存在 → 原样转发给 `app_addr`
   - 若源地址 == 某会话的 `app_addr` 且 `device_addr` 存在 → 原样转发给 `device_addr`
   - 否则丢弃（未配对或未知来源）
4. **超时清理**：每 10 秒扫描一次，任一 `last_seen` 超过 **30 秒** 的会话删除（对应客户端会持续发心跳自动重建）。
5. **日志级别**：注册/配对/清理打 INFO；转发不逐包打日志（可统计字节数，每分钟汇总一条 DEBUG）。

### 边界情况

- 同一 pair_code 的新注册覆盖旧地址（客户端重连/换网络自动恢复）。
- 多设备并存：pair_code 各不相同，互不影响。
- 服务器重启：会话表清空，客户端心跳自动重建（< 2 秒恢复）。

## 4. 参考实现要点（Python 3，无第三方依赖）

```python
# 伪代码骨架，智能体可按此实现
import socket, struct, time

PORT = 50123
sessions = {}          # pair_code -> {"dev": addr, "app": addr, "dev_t": t, "app_t": t}
sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.bind(("0.0.0.0", PORT))

def forward(src_addr, dst_addr, data):
    sock.sendto(data, dst_addr)   # 原样转发

while True:
    data, src = sock.recvfrom(2048)
    if len(data) >= 14 and data[0:4] == b"XZRG" and data[4] == 1:
        code = struct.unpack("<I", data[6:10])[0]
        s = sessions.setdefault(code, {"dev": None, "app": None, "dev_t": 0, "app_t": 0})
        s["dev"], s["dev_t"] = src, time.time()
    elif len(data) >= 14 and data[0:4] == b"XZRA" and data[4] == 1:
        code = struct.unpack("<I", data[6:10])[0]
        s = sessions.setdefault(code, {"dev": None, "app": None, "dev_t": 0, "app_t": 0})
        s["app"], s["app_t"] = src, time.time()
    else:
        # 按源地址匹配会话并转发
        for code, s in sessions.items():
            if src == s["dev"] and s["app"]:
                forward(src, s["app"], data); break
            if src == s["app"] and s["dev"]:
                forward(src, s["dev"], data); break
    # 周期性清理 last_seen > 30s 的会话
```

> 智能体注意：以上为行为骨架，请按第 3 节的完整规则实现（含超时清理、日志、异常处理），并用第 6 节步骤自测。

## 5. 部署与验收

### 5.1 部署要求

- 任意 Linux 服务器（云主机/内网机器做端口映射均可）
- 防火墙放行 UDP **50123**（如用其他端口请在交付说明中注明）
- 常驻运行（`systemd` / `nohup` / `screen` 均可）

### 5.2 自测步骤（后端可独立完成，无需真实设备）

用任意两台能上网的机器（或同一台机器两个进程）模拟：

1. 进程 A 循环发 XZRG（pair_code=0x12345678，每 2s），并监听本地 UDP 端口
2. 进程 B 循环发 XZRA（同 pair_code，每 2s），并监听本地 UDP 端口
3. 进程 A 再发任意测试包（如 `b"HELLO"`）→ **进程 B 应原样收到 `b"HELLO"`**
4. 反向同理（B 发任意包 → A 收到）
5. 停止进程 B 心跳 → 30 秒后服务器应清理会话；恢复心跳 → 2 秒内恢复转发

2. `UDP 端口`
3. 服务程序源码/部署路径（备查）
4. 确认 5.2 自测通过

## 7. 边界与非目标

- **不做**：音频转码、缓存、加密（演示项目；pair_code 4 字节为轻量配对，如需加固可后续协商 token 方案）
- **不做**：多对多群组、历史回放
- **QoS**：UDP 尽力而为；局域网丢包率极低，云端模式偶发丢帧由手机端 480ms 抖动缓冲吸收
- **负载**：单设备 32KB/s；若未来多台设备并发，本实现亦足够（每会话独立，内存占用 KB 级）
