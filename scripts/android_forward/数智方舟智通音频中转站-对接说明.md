# 数智方舟智通音频中转站 — 对接说明

> 本文档面向后端/联调老师，说明"小智终端（ESP32-P4）→ Android 手机 → 蓝牙耳机"音频中转链路的联合运作机制、网络协议与对接边界。

## 一、背景与目标

小智终端（ESP32-P4 开发板，4.3" 触屏）通过云端服务器与 LLM 交互，LLM 回复经 TTS 在**板载扬声器**播放。板载扬声器音质有限，且拍摄宣传片需要干净收音。

本方案将 LLM 回复音频**旁路转发**到局域网内的 Android 手机 App「数智方舟智通音频中转站」，由手机经系统路由输出到**蓝牙耳机**（或手机外放）。

**对后端的影响：零。** 服务器协议、TTS 链路、任何云端配置均无需改动——转发发生在设备本地播放出口的旁路上，服务器完全无感知。

## 二、系统架构

```
┌─────────────────────────────────────────────────────────────┐
│ 云端（无需改动）                                              │
│   LLM + TTS 服务器                                            │
│      │ WebSocket/MQTT（OPUS 编码，原有协议不变）                │
└──────┼──────────────────────────────────────────────────────┘
       ▼
┌─────────────────────────────────────────────────────────────┐
│ 小智终端（ESP32-P4 + C6，固件 main/audio/forwarder/）          │
│                                                              │
│  解码队列 → Opus 解码 → PCM 16kHz mono 16bit                  │
│        ├──→ AudioOutputTask ──→ 板载扬声器（可被静音短路）      │
│        └──→ AudioForwarder 旁路（新增，本地功能）               │
│               · 音频拆包 → UDP 单播 → 手机                      │
│               · XZAL keepalive 每秒 1 次                       │
│               · 监听 XZFA 广播自动发现手机 IP                   │
└──────┬──────────────────────────────────────────────────────┘
       │ 同一 WiFi 局域网（UDP）
       ▼
┌─────────────────────────────────────────────────────────────┐
│ Android 手机 App「数智方舟智通音频中转站」（前台服务，可锁屏）    │
│   AudioReceiver（UDP:50001，fragment 重组）                   │
│        → 抖动缓冲队列（8 帧，≈480ms）                          │
│        → AudioPump（AudioTrack 16kHz mono PCM_16BIT）         │
│        → 手机系统音频路由（自动）→ 蓝牙耳机 / 扬声器             │
│   AnnounceSender（每 2s 广播 XZFA）                            │
│   A2dpStatus（显示耳机连接状态，只读）                          │
└──────────────────────────────────────────────────────────────┘
```

**关键点**：蓝牙耳机的配对、连接、A2DP 编解码全由**手机操作系统**完成，App 只是普通媒体播放方，系统自动把音频路由到耳机。终端与耳机之间没有直接连接（ESP32-P4 配套的 C6 仅支持 BLE，无经典蓝牙 A2DP）。

## 三、网络协议（v1，全部小端字节序）

### 端口约定

| 方向 | 端口 | 内容 |
|---|---|---|
| App → 终端 | UDP **50000** | XZFA announce（广播） |
| 终端 → App | UDP **50001** | XZAD 音频帧 + XZAL keepalive（单播，或**组播** `239.255.1.1`——见下方组播模式） |

### 0. 组播模式（手机热点场景，实测可用）

终端设置页开启"组播模式"后，XZAD/XZAL 改发往**组播地址 `239.255.1.1:50001`**，包格式与单播完全一致。App 侧 MulticastSocket joinGroup 接收。

**关键价值**：Android 手机热点（tethering）模式下，热点客户端的进流量被系统 NAT 到移动网络、不投递本机 App（单播/广播均失效）；**组播包实测可穿透到达手机 App**（已实测通过）。这是"设备仅连手机热点、无服务器、无 root"场景的解决方案。

### 1. XZFA announce（App → 终端，广播，每 2s，12 字节）

```
offset 0  size 4  magic      'XZFA'
offset 4  size 1  version    0x01
offset 5  size 1  flags      0x00（保留）
offset 6  size 2  audio_port App 音频接收端口（默认 50001）
offset 8  size 4  app_seq    单调递增
```

终端行为：锁定**首个** announce 来源 IP 为目标；同源刷新活性；异源忽略（防多 App 互抢）；8 秒未收到 announce 判定 App 离线；App 重开或点击终端"重新搜索手机"后重新锁定。

### 2. XZAD 音频帧（终端 → App，单播，20 字节头 + PCM）

```
offset 0  size 4  magic       'XZAD'
offset 4  size 4  seq         帧序号（每帧 +1，同一帧的所有 fragment 共用）
offset 8  size 4  ts_ms       帧时间戳（透传服务器 AEC 时间戳，无则 0）
offset 12 size 2  sample_rate 16000
offset 14 size 2  channels    1
offset 16 size 2  samples     整帧样本数（恒 960 = 60ms）
offset 18 size 1  frag_index  本包 fragment 序号（0 起）
offset 19 size 1  frag_count  fragment 总数（1 = 未拆包）
offset 20 ...     pcm         int16 LE 样本
```

**拆包规则**：每包最多携带 500 样本（20 + 500×2 = 1020 字节 < MTU 1500），960 样本拆为 2 包（500 + 460）。**拆包是为了避免 IP 分片**——部分路由器/手机 WiFi 芯片会丢弃分片 UDP 包（实测电脑收分片正常、手机全丢）。接收方按 `seq + frag_index` 重组。

- 帧率：每秒约 16.67 帧（60ms/帧）
- 码率：16kHz × 16bit × 1ch = 256 kbps ≈ 32 KB/s，局域网负载可忽略
- 音频源：LLM 回复 TTS 的 OPUS 解码后 PCM；**不含**本地提示音/表情音（旁路挂点在播放出口且仅语音回复走此路径）

### 3. XZAL keepalive（终端 → App，单播，每 1s 无音频也发，8 字节）

```
offset 0  size 4  magic 'XZAL'
offset 4  size 4  seq   包序号
```

### 活性判定（双方一致）

- App：8 秒未收到 XZAD/XZAL → 显示"设备: 离线"
- 终端：8 秒未收到 XZFA → 显示"手机: 离线"，保留 IP 待恢复
- 恢复：App 重开/网络恢复后下一轮 announce 自动重连，无需人工干预

## 四、终端侧配置

设备"设置"页（右上角"设置"按钮）：

| 设置项 | 说明 | 持久化 |
|---|---|---|
| 转发到手机 | 总开关 | NVS `forward/enabled` |
| 转发时本地静音 | 开启后板载扬声器不响（拍摄模式） | NVS `forward/mute_local` |
| 组播模式 | **手机热点场景专用**：音频改发组播 239.255.1.1（家庭 WiFi 保持关闭用单播） | NVS `forward/multicast` |
| 音量 / 亮度 | 独立于转发，原有功能补 UI | NVS `audio/output_volume`、`display/brightness` |

**静音实现**：旁路挂点短路播放出口（不调 `SetOutputVolume`，不污染音量配置）。转发关闭时设备行为与未加功能前完全一致。

## 五、App 使用流程（联调参考）

1. 手机与终端连接**同一 WiFi**（同网段）
2. 手机系统蓝牙设置配对耳机（一次性）
3. 安装并打开「数智方舟智通音频中转站」→ 授权通知/蓝牙
4. App 自动广播 announce → 终端自动锁定（终端设置页可见"手机: x.x.x.x 在线"）
5. 对终端说话 → 音频从耳机/手机外放播出
6. App 为**前台服务**：锁屏、切换 App 后中转持续；下拉通知栏可见"运行中"；停止中转点 App 内"停止中转"按钮

## 六、联调排障速查

| 现象 | 排查 |
|---|---|
| App 显示"设备: 离线" | ① 手机/终端是否同一 WiFi（或热点场景确认已开"组播模式"）② 终端设置页"转发到手机"是否打开 ③ 路由器是否开启 AP/客户端隔离（关闭即可） |
| 有帧数但无声音 | 手机媒体音量；耳机是否已配对连接 |
| 帧数不涨、有爆音 | 看"欠载"数字；路由器 2.4G/5G 分频时终端与手机须同频段 |
| 声音断续 | 终端与路由器距离；换 5GHz 或靠近路由器 |
| 终端设置页显示"手机: 离线" | App 被杀（部分国产 ROM 需在电池设置里允许后台运行/自启动）；重开 App |

## 八、协议版本演进预留

- announce 包含 `version` 字段，终端校验 `== 0x01` 才接受，未来可平滑升级
- XZAD 头 `frag_count` 使拆包数可扩展（当前恒 2）
- App 对未知包静默忽略，向前兼容

## 九、修改 App 图标教程

默认 APK 使用系统通用图标，更换步骤如下：

1. **准备图标图**：正方形 PNG，建议 512×512 或更大（圆角/透明背景按需设计）
2. **生成各密度尺寸**（用 PS/美图/任意图片工具缩放，或在线工具）：
   | 目录 | 尺寸 |
   |---|---|
   | `app/src/main/res/mipmap-mdpi/ic_launcher.png` | 48×48 |
   | `app/src/main/res/mipmap-hdpi/ic_launcher.png` | 72×72 |
   | `app/src/main/res/mipmap-xhdpi/ic_launcher.png` | 96×96 |
   | `app/src/main/res/mipmap-xxhdpi/ic_launcher.png` | 144×144 |
   | `app/src/main/res/mipmap-xxxhdpi/ic_launcher.png` | 192×192 |

   偷懒做法：只放 `mipmap-xxxhdpi` 一张，系统会自动缩放适配其他密度。
3. **声明图标**：`app/src/main/AndroidManifest.xml` 的 `<application>` 标签内加：
   ```xml
   android:icon="@mipmap/ic_launcher"
   ```
4. **重新构建**（命令行）：
   ```bash
   gradle assembleDebug
   ```
5. 覆盖安装新 APK；若桌面图标未立即更新，删除桌面快捷方式后重新添加（或卸载重装）

> 附：有 Python + Pillow 环境的话可脚本化缩放：
> ```python
> from PIL import Image
> img = Image.open("icon.png")
> for size, dpi in [(48,"mdpi"),(72,"hdpi"),(96,"xhdpi"),(144,"xxhdpi"),(192,"xxxhdpi")]:
>     img.resize((size, size), Image.LANCZOS).save(f"app/src/main/res/mipmap-{dpi}/ic_launcher.png")
> ```

## 十、外网/外出场景（无公共 WiFi 时）

### 方案一：组播模式（✅ 已实测通过，首选）

外出时设备连**手机热点**、App 开组播模式（终端设置页打开"组播模式"开关）即可：

- 发现机制不变：App 的 XZFA announce 广播在热点下上行可达，终端照常锁定手机
- 音频下发改走**组播 `239.255.1.1:50001`**：Android tethering 对热点进流量的 NAT 拦截不作用于组播（已实测穿透）
- App 侧 MulticastSocket 已常驻 joinGroup，**无需任何切换操作**（单播/组播自动兼容）
- 零服务器、零 root、零额外硬件

> 备注：组播穿透已在测试机实测通过；不同 ROM 行为可能略有差异，若某机型不可用，回退方案二。

### 方案二：云端中转（备选，需后端老师支持）

终端连手机热点可正常访问外网（仅局域网互通受限）。将音频帧改为**经服务器中转**：

```
终端 ──XZAD 帧（复用现有格式）──▶ 云中转服务器 ──▶ App（移动网络拉流）
App ──控制/announce（简化）──▶ 服务器 ──▶ 终端
```

对接要点（供后端评估）：
- 终端侧：把 UDP 目标从"局域网手机 IP"改为"服务器地址"，每台设备带 UUID（板级 UUID 已有）作为会话标识
- 服务器侧：新增一条轻量双向通道（建议 UDP 或 WebSocket 二进制帧），按 UUID 配对设备与 App 会话；流量约 32 KB/s 单向音频 + 极小 keepalive
- App 侧：改连服务器地址，其余（重组/播放/耳机路由）不变
- 延迟代价：约增加 1~2 个 RTT（视服务器部署位置，一般 +50~300ms），对话体验仍可接受
- 优势：不受任何网络拓扑限制；与现有 LLM 服务器可共用基础设施
- 详细协议与实现规范见《云端透传-后端对接文档.md》（后端老师的 AI 助手可直接照此实现）

### 方案三：随身 WiFi（已不需要，仅作参考）

携带移动路由器（随身 WiFi，插流量卡），手机与终端都连随身 WiFi——与家庭场景完全一致。组播方案通过后无必要。
