如何DIY角色的形象
1. 手机/电脑 点击我方提供的云服务器IP/域名（我还在报备阶段），进入资源生成主页

2. 主页有三个功能板块： 制作角色形象 配置角色信息 选择制作角色形象，点击

3. 页面有提示“请将角色的静态立绘拖到此处”，拖进去，然后点击“下一步”按钮

4. 点击后进入框选页面，上方有提示“请将角色主体框选入白色框内”，正常框选，然后点击“下一步” 开始生成，点击后会出现“同时生成三个角色模型，请等待”

5. 状态等待页面有三个模型生成信息栏，会显示“running”“success”“fail+报错”三种状态，只有全部角色信息栏都出现“success”或“fail”才允许进入下一步 此时下面的“下一步”按钮会从灰色变为可以点击的绿色。用户点击即可。

6. 构建和检测过程是自动的，等待检测完成，会出现三个模型，用户可以看到在通行证中的预览情况，三选一，下面有个选择框，选择其中用户认为最满意的一张，点击“下一步”

7. 此时右侧会出现一堆参数条，实时展示模型的各个部分的参数，最右侧有AI助手，如果用户觉得哪里生成的不满意，就可以通过自然语言描述进行修正。 下方有一个PSD预览器，可以拖动以调整图层。

8.满意后直接点击“导出角色到个人仓库”即可。 导出的角色会自动保存到用户的云端空间，方便之后为其配Agent和音色

修改提示词
老师提出两个重要的修正点，第一个是目前管理员有一个仓库，用户克隆的角色资源也在仓库中，这样相当于一个副本存了两次甚至更多。
因此考虑OSS存储方案：
OSS：将角色打包为zip，OSS会提供一个永久链接，然后数据库存储这个链接，用户点击缩略图向数据库请求角色资源，鉴权后，找OSS把临时的key给用户，调用API获得zip，解压发给设备

然后对于管理员而言，保留原来的文件管理结构（用各级目录管理角色的PPD PPDQ cover voice等），这样方便我添加和查看各角色的情况与验证，每次做好一个角色，点击验收后，会自动压缩zip，并提交到OSS服务器。这样就不用在本地存大文件了。

然后把用户信息、Agent定义、模型绑定、zip存相对路径（拼接）等较小的信息存在本地数据库，大的zip（管理员和用户的）都扔到OSS中。

然后用户克隆角色后，不要复制一份公共仓库的角色到用户仓库，而是存一个指向公共仓库的“链接”，用户点进去看的时候和公共仓库一模一样，他没有权限修改这个克隆仓库的内容，必须保持和公共仓库一致。

注意，用户自创角色生成角色资源的时候，和管理员制作角色的逻辑一样，他自己验收后也压缩放到OSS中，他本地能修改自己创建的角色的资源文件夹（voice PPD PPDQ这些）。

用户的自创或克隆出来的Agent信息则允许修改。相当于前面将资源和AGent配置分开存储了，对于用户而言，克隆的角色的资源不允许更改，打包存在OSS；自创的角色的资源允许更高，也打包存在OSS； 对于用户的Agent信息，可以存在OSS的数据库或者本地数据库，反正要快！而且不能占太大空间，本地只有60G。

尽可能轻量化本地的存储，用数据库加速。

🔁 二、核心处理流程（端到端）
阶段 1️⃣：数据采集
输入：摄像头视频流
处理：
使用 MediaPipe Face Mesh 或自研模型提取瞳孔/眼球关键点
计算 3D gaze direction vector（单位向量 [gx, gy, gz]）
输出：每帧写入 gaze_vector.txttext

11770536177136,0.23,-0.45,0.87
阶段 2️⃣：环境感知（物体检测）
输入：同步视频帧（或独立图像）
处理：
使用 YOLOv5/v8 进行实时物体检测
将检测框中心坐标 归一化到 [0, 1000] 范围（便于与 gaze 坐标对齐）
输出：写入 recent_gaze_records.txttext

11770536177136,{"笔记本电脑":[703,451],"手机":[346,581]}

阶段 3️⃣：个性化标定（Calibration）
目的：建立 gaze vector → 屏幕坐标 的映射关系（因人而异）
流程：
用户点击 GUI 中的多个标定点（如九点网格）
系统同步记录：
当前 gaze vector（来自 gaze_vector.txt）
用户选择的真实世界坐标（如 (500, 300)）
构建训练集：{(gaze_vec_i, uv_i)}
训练轻量 MLP 映射模型：python

1nn.Sequential(
2    nn.Linear(3, 64),
3    nn.ReLU(),
4    nn.Linear(64, 32),
5    nn.ReLU(),
6    nn.Linear(32, 2)   # 输出 (u, v) in [0,1000]
7)
保存为 gaze_mapper.pth

阶段 4️⃣：实时推理与交互（Inference）
输入：
实时 gaze_vector.txt
实时 recent_gaze_records.txt
处理：
加载 gaze_mapper.pth
将 gaze vector 映射为屏幕坐标 (u, v)
计算该点到各物体中心的 欧氏距离
转换为 置信度：conf = max(0, 1 - distance / D_max)
输出：可视化窗口
中心红点：当前注视位置
白色同心圆：30px/60px/90px 置信区间
绿点 + 标签：检测到的物体
右侧列表：按置信度降序排列的物体

我负责的视线向量获取的思路是，克岩负责的那一块具体细节我不太清楚，但大概流程让AI帮忙总结了一下：

before中识别范围老飞到边缘直接用ROI限制砍了，
加一个三层的cascade二值化，再
瞳孔区域大小极其不稳定用滑动窗口 + 面积预热维护解决了，
瞳孔核心乱飞用视线状态机设定飘逸和稳定两个状态，维护历史15帧的核心位置，当有三帧落在判定半径50像素内就进入稳定态，只有稳定态才输出gaze_vector
为了避免眨眼时识别到其他暗色区域，采用回归恢复，当消失帧数低于8且下一次出现时核心与此前平均位置距离小于60像素时，判断为眨眼，不中断视线稳定状态计数器
最后加了滤波，取稳定状态下五帧的平均核心位置做投影，得到稳定的视线

🔁 二、核心处理流程（端到端）
阶段 1️⃣：数据采集
输入：摄像头视频流
处理：
使用 MediaPipe Face Mesh 或自研模型提取瞳孔/眼球关键点
计算 3D gaze direction vector（单位向量 [gx, gy, gz]）
输出：每帧写入 gaze_vector.txttext

11770536177136,0.23,-0.45,0.87
阶段 2️⃣：环境感知（物体检测）
输入：同步视频帧（或独立图像）
处理：
使用 YOLOv5/v8 进行实时物体检测
将检测框中心坐标 归一化到 [0, 1000] 范围（便于与 gaze 坐标对齐）
输出：写入 recent_gaze_records.txttext

11770536177136,{"笔记本电脑":[703,451],"手机":[346,581]}

阶段 3️⃣：个性化标定（Calibration）
目的：建立 gaze vector → 屏幕坐标 的映射关系（因人而异）
流程：
用户点击 GUI 中的多个标定点（如九点网格）
系统同步记录：
当前 gaze vector（来自 gaze_vector.txt）
用户选择的真实世界坐标（如 (500, 300)）
构建训练集：{(gaze_vec_i, uv_i)}
训练轻量 MLP 映射模型：python

1nn.Sequential(
2    nn.Linear(3, 64),
3    nn.ReLU(),
4    nn.Linear(64, 32),
5    nn.ReLU(),
6    nn.Linear(32, 2)   # 输出 (u, v) in [0,1000]
7)
保存为 gaze_mapper.pth

阶段 4️⃣：实时推理与交互（Inference）
输入：
实时 gaze_vector.txt
实时 recent_gaze_records.txt
处理：
加载 gaze_mapper.pth
将 gaze vector 映射为屏幕坐标 (u, v)
计算该点到各物体中心的 欧氏距离
转换为 置信度：conf = max(0, 1 - distance / D_max)
输出：可视化窗口
中心红点：当前注视位置
白色同心圆：30px/60px/90px 置信区间
绿点 + 标签：检测到的物体
右侧列表：按置信度降序排列的物体
