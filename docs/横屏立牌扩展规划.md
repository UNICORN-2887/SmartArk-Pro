## 0. Qlive2d 格式检查结论

`E:\Passport\source\立绘\产出\Qlive2d\Amiya` 的三个子目录（阿米娅正面/背面/基建）内容：

| 文件 | 类型 | 说明 |
|---|---|---|
| `char_002_amiya.skel` | **Spine 3.8.99 二进制骨骼文件** | 头部 hash+版本号 "3.8.99" 已确认 |
| `char_002_amiya.atlas` | Spine 图集描述 | 切图区域定义 |
| `char_002_amiya.png` | 图集纹理（41-100KB） | Q 版部件贴图 |

**结论：这不是 Live2D，是 Spine 骨骼动画**（明日方舟 Q 版小人标准格式）。现有两个引擎都用不了：
- `lv2_render`（自研 Live2D 渲染器）：吃自研 `model.l2d + keyforms.bin + tex_00.raw`，与 Spine 无关
- `lv2_parse_moc3`：解析 Cubism moc3，也不是 Spine

### 方案选择（推荐 B）

| 方案 | 评估 |
|---|---|
| A. 设备端写 Spine 运行时 | ~3000+ 行 C 解析+骨骼蒙皮渲染，P4 软渲染风险大，否决 |
| **B. PC 转换 Spine → 纸偶（PPD）格式** | ✅ **推荐**。Q 版小人 = region 图块 + 骨骼动画，与纸偶引擎"图层+支点+仿射动画"概念一一对应。PC 端 Python 转换器（解析 skel 3.8.99 + atlas 切图）→ 生成 PPD `scene.json + *.raw`，**设备端零新代码，直接走已验证 18fps 的 PPD 渲染管线，触摸互动/表情全继承** |
| C. 预渲染序列帧 | 无互动性，不满足"互动模式"要求 |

### ✅ 转换器已实现（tools/spine2ppd/，2026-08-26 完成）

放弃手写解析/几何（初版手算旋转角每层错 90°），改为 **vendored 官方 spine-runtimes
3.8.99.1（spine-canvas）+ 逐层官方渲染器导出**——旋转/mesh 形变/裁剪零手写几何：

- `render_layers.mjs`：每槽单独挂附件 → 官方渲染器画 480×800 缓冲 → 像素扫描 bbox →
  切出 `<槽名>.raw` + `scene.json`（33 层）
- 关键决策：**必须应用 Default 动画第 0 帧**（setup pose 同时含 5 套姿势骨骼链 + 表情
  变体，不应用会 5 只手 + 痛苦表情叠加）；bbox 只算当前挂载的可见附件；图层名用槽名
  （两槽可能挂同名附件）；导出对整幅做 180° 旋转（设备场景 y 向下、人物正立）
- 验收：`preview.png`（复合预览）与 `ref.png`（整身参考渲染）**像素级一致
  （mean diff 0.05/通道）**；33 层、单人单臂、正常表情
- 用法：`python convert.py <spine_dir> <out_dir> [scene_name]`（见 tools/spine2ppd/README.md）
- 产出：`E:\虚拟SD卡\main\operator\CASTER\5STAR\Amiya\PPD_Q\`（阿米娅正面，用户已确认）
