# 多用户系统与监控中心 — 设计计划(待审核)

> 状态:计划草案,用户审核后分阶段实施。2026-09-05

## 1. 目标

1. **管理员主页实时监控**:服务器状态(内存/CPU/流量包)+ 全部在用 API 余量(DeepSeek、Mem0、硅基流动音色克隆、RunningHub 币)
2. **多用户账号体系**:注册(邮箱+手机号+邮件验证码)→ 登录 → 三种角色(管理员/用户/资源组)→ 资源制作仅管理员+资源组可用
3. **用户私有仓库**:每用户自定义角色槽(管理员设定,预设 10)+ 只读共享的明日方舟公共角色库(与管理员实时一致)
4. 预留扩展:角色共享社区、密钥兑换官方角色(卡片)→ 用户私有仓库

## 2. 架构总览

```
                    ┌─────────────────────────────────────┐
                    │  Nginx(可选,后期 HTTPS 反向代理)      │
                    └──────┬──────────┬──────────┬─────────┘
                           │          │          │
          :88 xiaozhi-server   :7861 paperdoll_sim   :7862 dynamic_art
          (聊天+管理后台)      (资源生成+仓库 API)     (动态立绘工作台)
                           └────┬─────┴─────┬─────┘
                    共享会话:签名 Cookie(各服务同密钥验签)
                    ┌─────────────────────────────────────┐
                    │  MySQL/SQLite:用户/角色/配额/兑换码   │
                    └─────────────────────────────────────┘
  数据区:
    /opt/szfz/sdcard/Arknights/          公共角色库(管理员维护,全员只读)
    /opt/szfz/sdcard/_users/<uid>/roles/ 用户私有仓库(自定义角色槽)
```

### 会话方案
- 登录签发签名 Cookie(如 `szfz_session=<uid>.<exp>.<hmac>`,密钥各服务共享,存 `/opt/szfz/session_key`)
- 88/7861/7862 三个服务用同一验签逻辑(共享 python 模块 `szfz_auth.py`,与 cloud_repo.py 同样部署在 `/opt/szfz/`)
- 角色权限随会话携带(角色变更即时生效:管理员改权限 → 用户下次请求即失效/生效)

## 3. 数据库设计(SQLite 单文件,`/opt/szfz/szfz.db`)

```sql
users(id INTEGER PK, email TEXT UNIQUE, phone TEXT, password_hash TEXT,
      salt TEXT, role TEXT DEFAULT 'user',   -- admin | user | resource
      vip TEXT DEFAULT 'normal',             -- vip | normal(暂不区分)
      custom_slots INTEGER DEFAULT 10,       -- 管理员可调
      status TEXT DEFAULT 'active',          -- active | banned
      created_at TEXT)
verify_codes(email TEXT, code TEXT, purpose TEXT, expires_at TEXT)  -- 5 分钟有效
quota_daily(uid, date TEXT, ppd_used INT, dyn_used INT,
            ppd_limit INT DEFAULT 2, dyn_limit INT DEFAULT 5)       -- 预设,暂不开放
redeem_codes(code TEXT UNIQUE, role_pack TEXT, used_by TEXT NULL,   -- 预留:卡片密钥
             created_by TEXT, expires_at TEXT)
audit_log(id, uid, action TEXT, target TEXT, ts TEXT)               -- 关键操作审计
```

密码:bcrypt(salt + hash)。登录限流:同 IP/邮箱 5 次失败锁 10 分钟。验证码限频:每邮箱 1 封/分钟、每 IP 5 封/小时。

## 4. 阶段划分

### 阶段 1:账号体系 + 监控中心 + 用户仓库(核心)
1. **注册页**(88/admin 同级,公开 `/register`):邮箱+手机号+验证码(QQ 邮箱 SMTP,5 分钟有效)→ 注册即普通用户,出现在管理员面板
2. **登录页**:统一 `/login`,登录后跳回来源页(7861/7862 支持)
3. **鉴权中间件**:
   - 7861 资源生成页(workflow/spine2ppd/tuner/repo 写操作)→ 仅管理员+资源组
   - 7862 动态立绘工作台 → 仅管理员+资源组
   - 88 后台 → 仅管理员(现有 admin 账号体系迁移到新表)
4. **用户管理面板**(88/admin 新增):用户列表(邮箱/手机/角色/VIP/槽数/注册时间)、修改角色、收回权限(禁用)、调整槽数(预设 10)
5. **用户个人页**(88 新页 `/my`):我的仓库(私有区文件管理)+ 公共角色库(只读浏览/下载)+ 我的配额显示(2 次 PPD/5 次动态,暂不可用置灰)
6. **监控中心**(88/admin 主页):
   - 本机:CPU 占用/内存/SD 卡磁盘/网卡收发速率(psutil,10s 轮询)
   - 流量包:腾讯云 Lighthouse `DescribeInstancesTrafficPackages`(需提供 API 只读子账号密钥)
   - API 余量:
     - DeepSeek:余额查询接口(需提供 DeepSeek key,服务端已有?确认)
     - 硅基流动(音色克隆):`GET /v1/user/info` 查余额(用新 key)
     - Mem0:用量/额度接口(需查 Mem0 API,key 更换后配置)
     - RunningHub:币余量(现有 RH key,查 RH API 文档)
   - 页面每 30s 自动刷新;API 余量每 5 分钟拉一次(避免频繁请求)

### 阶段 2:用户角色操作面板 + 配额生效
- 用户版角色操作面板(88 `/my` 扩展):克隆音色、配置角色(编辑自己私有区角色资源)、自定义角色创建(槽位内)
- 配额计数落地:管理员+资源组打开资源制作时,调用资源生成 API 前扣减每日配额(暂不限制用户实际使用,先计数)
- 公共角色库与私有区的数据流:用户"收藏/复制公共角色到我的仓库"(复制目录)

### 阶段 3:预留扩展(仅设计,不实施)
- 角色共享社区:用户发布私有角色 → 公共共享区 → 他人一键复制到自己仓库(发布审核由管理员)
- 密钥兑换:卡片密钥 → `redeem_codes` 表校验 → 官方授权/隐藏角色复制到用户私有区
- 设备端绑定用户(如需要):设备绑定码 + 下载服务按用户分流
- HTTPS:域名备案完成后上 Let's Encrypt,所有页面强制跳转

## 6. 安全措施

1. bcrypt 密码;登录失败限流;验证码限频+过期
2. 会话 Cookie:HttpOnly + SameSite + HMAC 签名;无 HTTPS 期间 Cookie 明文风险在登录页注明
3. 所有 API key 存服务器 `/opt/szfz/config.json`(chmod 600),代码/前端零明文;对话中已暴露的 key 全部更换
4. 文件路径操作全部经 `_safe_rel` 校验(沿用 cloud_repo);用户私有区路径强制 `<uid>` 前缀
5. 审计日志:登录、角色变更、配额扣减、删除操作
6. 腾讯云密钥用只读子账号(仅 lighthouse 查询权限)

## 10. 唤醒词动态化(2026-09-05 实施)

固件 MultiNet 拼音命令词识别(无需训练),原为硬编码 9 词。改为服务器下发:

- **数据**:agents 表加 `wake_words` 列(拼音,分号分隔,如 `kai er xi;ni hao kai er xi`)
- **接口**:`GET /api/wakewords?mac=<设备mac>`(无鉴权,设备启动时拉取)
- **按用户隔离**:devices 表已有 user_id 列;用户在自己的 `/my` 页填设备 mac 绑定设备。
  拉取时返回该用户自己的角色(优先)+ 公共角色;与用户角色拼音重复的公共角色被**遮蔽**,
  避免 MultiNet 重复注册同一拼音——A 设备喊"凯尔希"用 A 后台配置的凯尔希,B 设备用 B 的
- **设备绑定接口**:`GET /my/devices`、`POST /my/devices/bind {mac}`、`POST /my/devices/unbind {mac}`;
  绑定校验设备未被其他用户绑定
- **固件**:`CustomWakeWord::SetWakeWordCommands()` 动态替换命令词表(延迟到检测停止时应用,避免并发改 multinet);
  `Application::FetchWakeWords()` 从 OTA 地址推导 http 地址拉取(注意:不能用 ws 的 89 端口推导)
- **未绑定即禁用**:拉取失败/未绑定 → `wake_words_state_=1` 拦截一切唤醒请求 + 状态栏"未绑定设备"
  + 全屏弹 6 位绑定码;后台轮询任务每 10s 静默重试,网页绑定成功后**自动解锁,无需重启**
- **注意**:拦截时不可用空命令表调 `esp_mn_commands_update()`——空表不更新,会保留 mn7_cn_ac
  模型内置的 313 条空调命令词
