# 《数智方舟》开题报告 PPT 制作要点（按页）

> 共 17 页正文 + 1 页备用预案。配色建议：深色底（#14161C 系）+ 高亮强调色（明日方舟标志性的橙金 #FF9F43 或原神金 #D4A853），字体统一思源黑体/OPPO Sans。
> 口径提醒：所有"成果"画面标注为**「原型验证」**；所有核心技术页只写**「思路」**，不写"已完成"。禁止出现"第七代""已结项"字样。
> 每页备注里标注了对应演讲稿段落与时间点。

## P1 封面
- **内容**：项目名《数智方舟》四个大字 + 副标题"随身智能体终端 · 让 TA 真正活一次" + 团队名（星马重工）+ 日期
- **视觉**：深色底 + 一台通行证实拍图居中偏下，角色立绘剪影或实机截图作背景暗纹；一行小字"山东大学 · 项目开题"
- **对应**：全篇开场前

## P2 三个灵魂拷问（引入页 1）
- **内容**：三个问题依次放大展示：
  1. 你还在为买不完的周边破费吗？
  2. 还记得那些让你意难平的剧情吗？
  3. 有没有想象过，TA 开口对你说话的那一天？
- **视觉**：每条配一张对应 IP 的官方立绘/名场面截图（方舟、原神、星穹铁道各一张），问题文字叠加在图上；最后一行小字"如果，这一切不再只是'如果'？"
- **对应**：演讲稿 0:00–2:00

## P3 产品是什么（定义页）
- **内容**：一句话定义——"只要一张图片，10 分钟，让你喜欢的角色开口说话、看见你、触碰到你"；产品形态：可挂包随身携带的"通行证"终端
- **视觉**：设备实拍大图（挂绳版），旁边标出触屏/喇叭/摄像头位置；若带设备，这页直接举实物
- **对应**：2:00–2:30

## P4 五大亮点（核心功能页）
- **内容**：五条亮点，每条配小图标：
  1. 一张图复活你的角色——10 分钟全自动，400+ 公共库一键克隆
  2. 像真人一样的对话——独立人设 + 原 CV 音色克隆 + 喊名字唤醒
  3. 看得见摸得到的陪伴——摸头眯眼、视线跟随、表情联动、机械臂
  4. 极高自定义——人设/音色/时装/背景/Q 版/自创 OC
  5. 开箱即用 + 互动社区——云端同步、手机端制作、共享验收体系
- **视觉**：五行卡片式布局；1、3 条放实机截图或 GIF（标注"原型验证"），2 条放声波图标
- **对应**：2:30–5:00

## P6 市面产品的五个不足（痛点页）
- **内容**：五条并列：
  1. 自定义不足——角色无限，没有产品支持无限定制
  2. 价格高昂——为"通用 AI 朋友"付费不值
  3. 不便携、无社交——谷子的灵魂是"展示"，软件给不了
  4. 参与度低——只能对话，不能陪伴生活
  5. **都不是"那个角色"**——形象相似、音色合成，老玩家一眼出戏
- **视觉**：五张卡片，第 5 条放大高亮（这是你们的差异化定位）；每张卡片下用一行小字给一句"我们的解法"
- **对应**：6:00–7:30

## P7 漫展故事 + 圈子共性（需求验证页）

## P9 技术脉络：四层架构总图（转折页）
- **内容**：一张纵向流程图：
  1. 内容层：一张静图 → 自动拆解 → 动态化 → 模型转换
  2. 设备层：ESP32-P4 触屏终端 + 自研动态角色渲染引擎
  3. 云端层：LLM + ASR + TTS + 音色克隆 + 记忆知识库 + 用户仓库社区

- **对应**：9:00–11:00

## P10 难点一：单片机里的动态角色引擎 ★
- **标题**：32MB 内存，怎么让十万顶点的 Live2D 跑起来？
- **内容**：
  - 矛盾：桌面引擎（Cubism/Spine）+ GPU vs ESP32-P4 单片机 32MB、无桌面 GPU
  - 思路 ①：自研轻量模型格式——定点化压缩、动画按需裁剪、无用网格不加载
  - 思路 ②：渲染引擎从零手写——软光栅化、Alpha 混合、遮罩裁剪、关键帧变形
  - 思路 ③：多形态降级——跑不动就切减载形态，维持"活人感"
  - 验收标准：帧率不掉、角色不糊、摸 TA 有即时反馈
- **视觉**：左侧放"10 万+ 顶点"大字 vs "32MB"大字对比；右侧三条思路做成齿轮流程图
- **对应**：11:00–12:30
- **备注**：这张是全场技术浓度最高的页，讲慢一点

## P11 难点二：一张图 → 动态角色的自动流水线 ★
- **标题**：427 个角色，人做不完——只能让工作流来做
- **内容**：四道工序流程图：
  - 拆解（语义分割大模型，按部位分层：头发/五官/身体/配件）
  - 动态化（图生视频路线 vs 参数化动画路线，对比验证中）
  - 绑定建模（图层 + 支点 + 关节，纸偶化结构）
  - 自动质检（图层/动画/设备端可跑性，不合格自动重试）
- **视觉**：横版流水线图，四道工序四色块；起点放一张静态立绘缩略图，终点放动态 GIF（标注"原型验证"）
- **对应**：12:30–13:30

## P12 难点三：原装的声音、性格与记忆 ★
- **标题**：能聊天不难，难的是聊天的"就是 TA"
- **内容**：
  - 音色：几秒原声 → 克隆 → 十几秒出模型，目标"以假乱真"
  - 人格：人设提示词 + 世界观知识库 + 人物关系网（RAG 检索增强）
  - 记忆：记住名字、生日、聊过的每件小事——长期记忆的存储、压缩、时机触发
- **视觉**：三角布局，中心是角色头像，三个顶点分别是"声音/人格/记忆"三个图标
- **对应**：13:30–14:30

## P13 难点四：用户多了，工程问题会吃掉一切 ★
- **标题**：技术跑通是一回事，服务一千个用户是另一回事
- **内容**：三行大字：
  - 并发压力——每次对话都在烧云端算力，成本怎么摊薄
  - 更新与修复——设备在用户手里，OTA 增量更新从第一天就要设计
  - 存储与安全——海量自创角色与私人记忆：对象存储+数据库混合架构、资源与人格分离、全链路鉴权
- **视觉**：三张警示卡（黄/橙/红），每张一句"如果不做好的后果"
- **对应**：14:30–15:45
- **备注**：结尾一句收束："任何一个做不好，前面三个难点全部白做"——承上启下
